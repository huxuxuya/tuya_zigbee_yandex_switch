# TLSRPGM tools

Локальный набор взят из https://github.com/pvvx/TLSRPGM (`sources/UART2SWire` и `tb-0x-pgm`).
Лицензия исходного проекта сохранена в `LICENSE-pvvx`.

## Файлы

- `TlsrComProg.py` — первоначальная загрузка через CH340 и временную перемычку.
- `floader.bin` — временный RAM-загрузчик, 1960 байт.
- `uart2swire.bin` — прошивка программатора для TB-04, 4616 байт.
- `TlsrPgm.py` — работа с готовым UART2SWire-программатором.
- `TB-04-KIT-PGM.gif`, `TB-04-kit-pgm.jpg` — схема временной перемычки.
- `TB-04-com-prog.gif`, `schematic.gif` — альтернативная двунаправленная схема USB-UART/SWire.
- `README-pvvx.md` — исходная инструкция pvvx.

## Локальное исправление TlsrComProg.py

Оригинал использовал ответы по 1024 байта. Через CH340C и USB passthrough VMware это периодически переполняло буфер. Кроме того, ветка retry печатала `Error 1`, но безусловно выходила из цикла и могла записать неполный блок в дамп.

Изменено только чтение flash:

- размер блока уменьшен с 1024 до 256 байт;
- число попыток увеличено с 2 до 10;
- после ошибки добавлена пауза 50 мс и настоящий повтор того же адреса;
- операции записи/стирания не изменялись.

Именно исправленной версией получены два совпадающих дампа TB-04.

## Локальное исправление TlsrPgm.py

Чтение flash повторяет сбойный блок до 10 раз с паузой 50 мс. Операции записи и стирания не изменялись. Вместе со снижением скорости SWire до 0.48 Мбит/с (`-d10`) это позволило получить два совпадающих дампа ZT3L через CH340C непосредственно в macOS.

## WCH driver

Официальный macOS-драйвер сохранен в `../wch-driver/CH34xVCPDriver.dmg`.

SHA-256:

```text
161f61a5c7a0de34ed056c76cc21cb9a32ab94a03a0084f91054ea53e9ec2dc8
```

Он успешно активирован как `cn.wch.CH34xVCPDriver`, но не исправил прерывания SWire-потока в macOS. Для программирования TB-04 использовался Linux USB passthrough.
